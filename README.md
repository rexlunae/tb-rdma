# tb-rdma

RDMA over USB4/Thunderbolt for Linux, written in Rust. Two profiles:

- `tb-uc`: Apple-compatible (UC QPs, Send/Receive only), for interop with Thunderbolt 5 Macs (macOS 26.2+, see Apple TN3205).
- `tb-rc`: native reliable connection with Write/Read/atomics and multi-hop forwarding, Linux-to-Linux.

Design document: https://claude.ai/code/artifact/a6266a1d-738f-4775-a55b-6252ddaf821a

## Status

Pre-alpha. Nothing here talks to hardware yet. The Apple wire format is unpublished, so `tb-uc` is a hypothesis until validated against a real Mac.

| Crate | State |
|---|---|
| `tb-rdma-proto` | Wire header, RETH, opcodes, strict decode, fuzz-style test. `#![no_std]`, zero dependencies, `core` only. Layout provisional. |
| `tb-rdma-core` | Credit pool (reserved control class), type-state QP, BFS router with TTL, in-memory virtual ring, 3-node forwarding test. Host-side `std` model. |
| `kernel/` | Not started. See `kernel/README.md`. |

## Byte order

Little-endian. Every host this targets (x86, ARM, Apple silicon) is little-endian, and the existing Thunderbolt stack agrees: Linux `thunderbolt-net` frame headers are `__le32`/`__le16`, and hellas-ai/thunderbolt-ibverbs writes its native header with `le` helpers. InfiniBand/RoCE/iWARP use big-endian only as network-byte-order legacy, which does not apply on a point-to-point link.

## Kernel constraints

The kernel has no `std`, builds with kbuild rather than cargo, and does not resolve crates.io dependencies or third-party proc-macros. So `tb-rdma-proto` is a hand-written codec on `core` only (`to_le_bytes`/`from_le_bytes`), with no dependencies, and its source can be compiled directly by kbuild.

`crates/tb-rdma-proto/tests/oracle.rs` cross-checks the codec byte for byte against an independent layout generated by `simple_endian`'s `#[derive(Endianize)]` (dev-dependency, host-only). The derive's `no_std` support depends on rexlunae/simple-endian-rs#19.

`tb-rdma-core` is still a `std` host model. The kernel layer should use the in-tree Rust `kernel` crate (`xarray`, `rbtree`, `sync`, `workqueue`, `dma`, `transmute`, fallible `kernel::alloc`) rather than a generic `no_std` port; the mapping and the gaps (no Thunderbolt, RDMA or endian abstractions) are in `kernel/README.md`.
